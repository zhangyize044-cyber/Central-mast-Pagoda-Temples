# 设计笔记：关键判断与踩坑记录

> 这份文档记录的是**为什么这么做**，不是做了什么。README 讲结果，这里讲取舍。
>
> 一个古建筑重建项目真正的门槛不在建模软件操作，而在三个地方：形制读得对不对、渲染骗不骗得过眼睛、以及能不能在不毁掉主体的情况下反复试错。

---

## 一、为什么是参数化，不是手工建模

手工建模的原型是"这一个"——改了层数就得重做一遍。参数化的原型是"这一类"——层数、层高、收分是变量，塔是算出来的。

这个选择在后期一次性回本：项目中期需要从 v2 升级到 v3、需要加雪景、加黄昏、加分期、加动画，**六条场景线全部建立在同一套几何生成代码之上**。如果当初是手工拖出来的，每一次氛围迭代都要重新确认几何没被动过。

代价也很实在：参数化写不出手工雕刻的随机性。所以程序化材质、构件库、随机种子这几件事必须做扎实，否则出来的是"精确但死板"的模型——比手工建模更假。

---

## 二、形制上的三个判断

### 1. 砖木分期必须体现在几何上，不是只体现在颜色上

一至三层是**砖构**（宋代在唐塔残址上重修），斗拱为砖仿木；四层以上斗拱及各层檐是**木构**（金代重建）。这不是配色差异，是两套建造逻辑。

如果只在材质上换个色，观众看到的是"一座塔被染了两种颜色"。所以砖构段的斗拱用砖砌逻辑（体块、无出跳深），木构段用真实的栱昂出跳。分期的可信度来自几何，颜色只是提示。

### 2. 塔心柱决定了这个项目该做剖视

四层起立木质塔心柱，长 17 m，八根扒梁放射状连接塔壁转角。罗哲文先生的评价是"我国现存实物中，仅正定天宁寺木塔尚存这一种结构方式"。

**这是整座塔最不可替代的一点。** 所以剖视不是一个炫技功能，是这个项目最该被看见的东西——外壳可以做得再漂亮，那也是复原想象；塔心柱的结构逻辑才是它在中国建筑史上的位置。

### 3. 塔院有相当一部分是推定的，必须说清楚

史料只记载了「重门—塔」这一段。牌坊、石渠、石桥、前殿遗址是按同期寺院制度推定的。

这里有个诱惑：把推定部分做得同样精致，整体观感会更完整。但文保类项目里，**含混比缺失更糟糕**。所以页面和片尾都明确标注了"示意性重建、复原部分为推定、不可作修缮依据"。

## 三、建模层：五个改了才对的坑

### 1. `bmesh.ops.recalc_face_normals` 会整体翻面

屋面、铺地都是开放面片，没有封闭体积，重算法线后 100% 朝下——渲染出来是黑的。

最后去掉这一步，靠生成时控制顶点绕序，配合双面材质解决。**不要对开放面片用重算法线。**

### 2. 拱洞别砌死

第一版石桥把拱洞用实心墙填了，形同路堤。桥必须做出**拱腹、券脸、拱肩**三段才成立。这类"看起来是个形状、实际少了结构层"的错误，在快速建模里极常见。

### 3. 硬山必须有山墙

只做盒子 + 屋顶，山墙位置会漏空。用 `roof(..., gb=h)` 按举折曲线生成曲边三角扇补上。

### 4. 歇山山花别用瓦材质

山花是抹灰/木板，用瓦材质会变成屋顶上一个灰色三角洞。正确写法：`roof(..., sh=P["plaster"], bf=P["wood"])`。

### 5. 掠射角贴图会糊成色块

铺地全程是掠射观看，glTF 里不带 `anisotropy`，mipmap 一路取平均，几十米外就是一块均匀褐色。前端加载后统一把 `map.anisotropy` 设为设备上限（通常 16），砖缝才回来。

---

## 四、贴图与色彩空间：三个一踩就黑的地方

1. **色彩空间双向转换**：`bpy.data.images.pixels` 是线性缓冲，存 PNG 时会编码成 sRGB。写入前必须把 sRGB 值转成线性（`lin()`），否则贴图整体提亮一档。
2. **`baseColorFactor` 与贴图相乘**：Blender 里给 Base Color 接了贴图，但 `default_value` 还留着深色，glTF 导出后变成「贴图 × 深色」，塔身直接黑成剪影。**接贴图后必须把 `default_value` 置白。**
3. **UV 超出 0–1**：三平面投影的 UV 范围是 0–几十，材质节点 `extension` 必须设 `REPEAT`，否则采样全部钳在边缘像素上。

## 五、渲染层：EEVEE Next 的脾气

### 1. EEVEE Next 读不到 CORNER 域的 `FLOAT_COLOR` 顶点色

`ShaderNodeAttribute` 和 `ShaderNodeVertexColor` 都会退回默认白。后果很直观：石板亮成米白格子、落叶变白点、青烟变成不透明光柱。

诊断方式不是猜——把对象材质临时换成固定暗 Emission，再整体隐藏 `D_*` 各渲一张低采样图，对比定位到顶点色这一层。

**修法：所有细节材质改为纯程序化**（Voronoi 色阶 / Noise 色表 / Generated 坐标渐隐），彻底不依赖顶点色。

### 2. 浅色在夜景里会数量级过曝

32 盏灯 + exposure 1.25，会把浅色漫反射直接推到饱和。原 `S_Paving` 有距离淡出压着，新加的石板没有，0.06 的 Base Color 已经过曝。

压到 **0.008–0.022** 量级才在夜景里呈深灰、同时仍被暖光局部点亮。

> 教训：调暗 40% 是看不出变化的，**得按数量级调**。

### 3. 一个暖光会把所有材质染成同一个颜色

纯暖光下灰瓦、红墙、青砖全部变成同一个橙棕，画面"平"。加一盏冷调补光让阴影走蓝灰，材质才重新分层。

### 4. Blender 4.4 换过 Glare 节点接口

`threshold` / `size` 属性已废弃，实际生效的是输入 socket `Threshold` / `Strength` / `Size`；更坑的是 `mix` 属性存盘后会被重映射（赋 0.0 读回 −0.45）。

改为取 `Glare` 纯光晕输出，用 `MixRGB(ADD)` 手动叠回原图，强度才可控。

### 5. 鸟瞰里不能用水平大平面做远景雾

它会被看成"地面本身"，把整片地面染成橙色并抬出一条硬地平线。改竖直雾幕又会露出横向矩形边。

最终停用该层，远景融合交给 `S_Paving` 的远端 Emission 完成。青烟密度也要极低（0.065），否则 Fog Glow 会把它放大成探照灯似的光柱。

## 六、动画层：四个绕不开的判断

### 1. 相机切换不能用 `scene.camera` 关键帧

它是指针，不可动画。改用 **timeline marker** 切机位：`f1` 全景 / `f97` 斗拱特写 / `f139` 剖视 / `f193` 回全景，并补了基线缺的两台相机。

### 2. 天空七段色标不做动画

蓝调黄昏是这套场景的视觉签名，硬改色标会闪帧。「压一档 / 入夜」改由 `Background.Strength`（1.0 → 0.86 → 0.34 剖视 → 0.48 夜景）+ exposure + 环境背景强度 + 星点可见性 + 暖灯能量共同实现。

**能不动的东西不要动，用外围参数表达变化。**

### 3. 逐层点灯只加分层灯没有用

塔身原本已被 4 盏 `Facade_*` 和 14000 W 的 `Dusk_Form_High` 照亮，9 盏新增灯完全被淹没。

改成「9 盏分层灯 + 4 盏 Facade 同步做九级阶梯」：点灯前塔身是冷白剪影，灯火自下而上把塔染成暖金——节奏才成立。

> 加了新东西却看不见，先别调新东西，去看原有的东西有多强。

### 4. 剖视必须做暗场

第一版外壳一隐，裸露的 `Heart_Column_Braces` 被 14000 W 冷白柔光照成纯白发光骨架，像医学插图。

修法是剖开瞬间同步：关九级灯、`Facade` 压到 22%、`Dusk_Form_High` 压到 8%、天空压到 0.34。柱体材质 Base Color 在剖视段压成深棕——**保留吃光能力**，八根扒梁灯才能读出依次亮；纯 Emission 完全不吃光，就没这个效果。

外壳瞬隐用 `hide_render` 关键帧 + **CONSTANT 插值**，隐藏 7 个上部对象，下三层砖塔心室保持实体；`Cam_06` 退到约 60 m、lens 38 mm，把 z 2–36 m 全塔收进画——否则剖视会变成悬空骨架。

## 七、工程层：为什么敢反复试错

核心约束只有一条：**主体几何不许动。**

在这条约束下，所有呈现层迭代都做成**独立增量脚本 + 独立 `.blend` + 独立集合**：

| 场景线 | 脚本 | 产物集合 |
| :--- | :--- | :--- |
| ① 夜景母版 | `build_scene.py` | 合并场景 |
| ② 雪景 | `add_snow.py` / `refine_snow_r2.py` | `05 精修 R2` |
| ③ 蓝调黄昏 | `add_dusk.py` | 独立 `.blend` |
| ④ 砖木分期 | `add_period.py` | `06 砖木分期` |
| ⑤ 22 s 动画 | `build_animation.py` | `07 动画层` |
| ⑥ 结构 Reveal | `add_reveal.py` | `08 开场 Reveal` |

每一层都能**整层删除回退**，前一层的时间戳一个没变。这带来的不是洁癖，是**允许失败**——雪景重做了一版 R2、分期染色做了三轮极端诊断、动画修了五轮，都因为可以整层扔掉才敢试。

### 配乐也是这套逻辑

本机没有音源素材，系统 Python 连 numpy 都没有，但 Blender 4.4 自带 numpy 1.26。所以用 `compose_score.py` 程序化合成：钟磬（非谐波泛音 + 金属起音）、鼓（pitch sweep + 低通噪声）、木构点击（噪声 + 共振峰）、弦垫（谐波叠加 + chorus）、合成混响（FFT 卷积）。

关键是**按节拍表写，不是贴氛围乐**：90 BPM 拍长 2/3 s，网格起点放在 `t = 1/6 s`，则 3.5 s = 第 5 拍、11.5 s = 第 17 拍——两个硬重音正好落在小节线上。从 0 起拍会偏四分之一拍。

数值复核：峰值 0.89、零削波；重音前→后 RMS 分别是 `0.0157→0.2866`、`0.0088→0.3613`，硬跳成立。

## 八、编码：外部 ffmpeg 是 0 字节空壳

本机 `ffmpeg` 不可用（文件存在但 0 字节）。改用 **Blender 内置 libavcodec 的 VSE** 编码：视频 H.264、音频 AAC 192 kbps / 48 kHz 立体声，全程不依赖外部工具。

成片回读校验（不是看文件大小，是真的解码）：视频 1600×900 / 528 帧 / 24 fps，音轨 528 帧 / 22.000 s，MP4 同时含 `soun` / `mp4a` / `vide` atom。

## 九、已知遗留

1. **仰视机位翼角有夜景高光带**：v2 就存在，v3 细节密度提高后略放大。对材质、上射灯、瓦垄面数、起翘量分别验证过，均不能根除，判断是展示层多光源 + ACES + 泛光的组合效应，不是几何缺陷。需要单独做一轮夜景调光。
2. **暖光带在剖视暗场里仍横穿画面中部**：属黄昏视觉签名，没有为剖视单独改天空——改了就不像同一个场景了。
3. **Blender 视口与网页观感不可能像素级一致**：AgX + Fog Glow 与 ACES + UnrealBloomPass 是两套不同的色调映射与泛光实现，暖光带位置和光晕形态本来就不同。这点从一开始就没打算对齐。

---

## 十、如果重做一次，会先做什么

1. **先定色调映射链路，再建模。** 中途在 AgX 和 ACES 之间摇摆过一次，返工了不少材质亮度。
2. **先做数值诊断工具，再做视觉调整。** 顶点色失效、过曝数量级、剖视白骨架这三件事，都是"渲一张对比图 + 查数值"解决的，靠肉眼调会绕很久。
3. **先写节拍表，再做动画。** 22 秒里两个重音的位置一定，机位和灯光才有对齐的锚点。
